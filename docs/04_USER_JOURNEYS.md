# 04. User Journeys

| 항목 | 내용 |
|---|---|
| 문서 상태 | Draft v0.1 (Step 3) |
| 작성일 | 2026-09-07 |
| 선행 문서 | 02_PRD, 03_MVP_SCOPE |
| 관련 문서 | 05_INFORMATION_ARCHITECTURE, 06_SCREEN_REQUIREMENTS |

이 문서는 사용자가 서비스를 어떤 순서로 겪는지를 정의한다. 화면의 구체적 구성은 06, 인터랙션은 07에서 다룬다. 등장인물은 예시이며, "나"는 현재 사용자다.

**등장인물 규약**: 표시명이 닉네임인 사람은 `@달리기왕`, 실명인 사람은 `김지수(실명)`으로 적는다.

---

## J0. 최초 진입 (Onboarding)

| 항목 | 내용 |
|---|---|
| User Goal | 최소한의 입력으로 "나와 비슷한 사람이 있긴 한가"를 빨리 보고 싶다 |
| Trigger | 조직 내부에 공유된 초대 링크를 눌렀다 |
| 전제 | 초대 링크 없이 접근하면 가입할 수 없다 (FR-0.2) |

### 흐름

| 단계 | User Action | System Response |
|---|---|---|
| 1 | 초대 링크로 진입 | 서비스가 무엇인지 세 문장으로 설명: 관심사로 사람을 발견하고, 서로 의사를 확인하면, 사내 메신저에서 대화한다. "실명은 연결이 성립될 때만 공개됩니다"를 이 시점에 보여준다 |
| 2 | Google 계정으로 로그인 | 계정 연결 완료. 소셜 계정의 이름은 가져오되 실명으로 확정하지 않는다 |
| 3 | 실명 입력 (이름 + 반) | "최준환_서울_18반" 형식으로 조합해 미리 보여준다. 사내 메신저 표시명과 같아야 하며 연결 성립 시 상대에게 공개된다는 설명과 함께 |
| 4 | 표시명 선택: 닉네임 입력 또는 "실명으로 활동" 선택 | 닉네임이면 중복·규칙 검사. 실명이면 "연결 전에도 실명이 보입니다" 확인. 표시명은 나중에 바꿀 수 있음을 안내 |
| 5 | 관심사 선택 (Category별 목록, 검색 가능) | 선택 개수와 최소/최대 `[P-01]`/`[P-02]` 안내. 최소 미만이면 완료 불가. 원하는 관심사가 없으면 "제안하기" 진입점 |
| 6 | 완료 | 알림 설정 안내: 이메일은 기본 켜짐, 브라우저 알림은 허용 권유(강요 없음). "요청이 오면 여기로 알려드립니다" |
| 7 | 그래프 진입 | 나를 중심으로 한 부분 그래프. 첫 진입 시 "사람이나 관심사를 눌러보세요" 안내와 "나와 비슷한 사람 보기" 진입점 |

### Decision Point

- 4단계: 닉네임 vs 실명. 사용자의 노출 성향에 따른 선택. 시스템은 어느 쪽도 기본값으로 밀지 않되, 각 선택의 결과(언제 누구에게 무엇이 보이는지)를 명확히 보여준다.
- 5단계: 관심사 몇 개를 고를 것인가. 시스템은 "N개 이상 고르면 추천이 생길 가능성이 높아집니다"로 유도한다.

### Success State

- 관심사 `[P-01]`개 이상 등록, 그래프 진입, 첫 화면에서 사람이 최소 한 명 이상 보인다.

### Failure / Exit State

| 상황 | 대응 |
|---|---|
| 초대 링크 없이 진입 | "초대 링크가 필요합니다" 안내. 가입 불가 |
| 실명 입력 없이 이탈 | 다음 진입 시 3단계부터 재개 |
| 관심사 최소 미만에서 이탈 | 다음 진입 시 5단계부터 재개. 그래프 진입 불가 (FR-1.6) |
| 원하는 관심사가 목록에 없음 | 제안하기로 이름을 남기고, 있는 것 중에서 최소 개수를 채우도록 안내 |
| 관심사를 다 골랐는데 그래프에 사람이 없음 | 초기 사용자 부족. "아직 참여한 사람이 적습니다. 알림을 켜두면 비슷한 사람이 생길 때 알려드립니다" |

## J1. Interest Discovery

| 항목 | 내용 |
|---|---|
| User Goal | 특정 주제로 이야기할 사람을 찾고 싶다 |
| Trigger | 그래프에서 관심사 노드가 눈에 들어왔다 / 특정 주제로 사람을 찾고 싶어 들어왔다 |

### 흐름

| 단계 | User Action | System Response |
|---|---|---|
| 1 | 그래프에서 관심사(예: #백엔드) 클릭 | Interest Focus: 그 관심사를 가진 사람만 강조, 나머지 흐림. 사이드 패널에 관심사 상세: 사람 수, 사람 목록(나와 공통 관심사 많은 순), 최근 글(있을 때) |
| 2 | 사람 목록 훑기 | 각 사람에 표시명, 나와 공통 관심사 개수, 연결 상태 표시 |
| 3 | 글 읽기 (S1 포함 시) | 작성자 표시명, 내용, 시간. 작성자를 누르면 Person Profile |
| 4 | 사람 클릭 | Person Focus로 전환. 그 사람의 관심사 강조, 공통 관심사 구분 표시. 사이드 패널이 Person Profile로 바뀜 |
| 5 | (선택) 다른 관심사로 이동 | 그 사람의 관심사 중 하나를 누르면 그 관심사 주변으로 탐색 범위 이동 |

### Decision Point

- 2단계: 누구를 볼 것인가. 시스템은 나와 공통 관심사가 많은 순으로 정렬해 판단을 돕는다.
- 4단계 이후: 요청을 보낼 것인가 → J2로 이어진다.

### Success State

- 관심사에서 출발해 최소 한 명의 Person Profile을 열었다.

### Failure / Exit State

| 상황 | 대응 |
|---|---|
| 그 관심사를 가진 사람이 나뿐 | "아직 이 관심사를 가진 다른 사람이 없습니다. 글을 남겨두면 나중에 오는 사람이 볼 수 있습니다" |
| 사람이 너무 많음 (상한 초과) | 그래프에는 관련도 상위만 표시하고 "N명 더 있음"을 목록에서 이어 봄 |
| 글이 없음 | "이 관심사로 이야기하고 싶은 것을 남겨보세요" 빈 상태 |
| 관심 있는 사람이 이미 연결됨 / 요청 진행 중 | 프로필에 상태 표시. 요청 버튼 대신 현재 상태와 가능한 행동만 |

## J2. Person Discovery → Connection (요청을 보내는 쪽)

| 항목 | 내용 |
|---|---|
| User Goal | 이 사람과 이야기해보고 싶다. 부담 없이 의사를 전하고 싶다 |
| Trigger | J1, J4에서 Person Profile에 도달했다 |

### 흐름

| 단계 | User Action | System Response |
|---|---|---|
| 1 | Person Profile 확인 | 표시명(실명 여부 표시), 관심사 전체, 나와 공통 관심사와 개수, 연결 상태, 최근 글 |
| 2 | "연결 요청" 클릭 | 요청 작성 화면. 공통 관심사가 미리 보이고, 메시지 입력(필수, 길이 상한). "상대가 수락하면 서로 실명이 공개됩니다" 안내 |
| 3 | 메시지 작성 후 전송 | "요청을 보냈습니다" 확인. 프로필의 상태가 "요청 보냄"으로 바뀜. 남은 요청 횟수 `[P-06]` 표시 |
| 4 | 대기 | 보낸 요청 목록에서 상태 확인 가능. 처리 전까지 취소 가능(S6) |
| 5a | 상대가 수락 | 알림(이메일/브라우저/앱 내): "○○님이 수락했습니다". 알림에서 한 번에 연결 성립 화면으로 |
| 6a | 연결 성립 화면 확인 | 상대 실명, 공통 관심사, 내가 보낸 메시지. **Action 안내**: "민수님, 사내 메신저에서 김지수님을 찾아 첫 메시지를 보내주세요." "메신저에서 메시지를 보냈어요" 버튼 |
| 7a | 사내 메신저로 이동해 첫 메시지 | 서비스 밖. 돌아와서 "메신저에서 메시지를 보냈어요"를 누르면 상태 반영 |
| 8a | `[P-11]`일 후 | 시작 표시가 없으면 나에게 "아직 연락하지 않으셨다면 지금 보내보세요" 재안내 |
| 9a | 성립 후 `[P-18]` 2일 | "대화를 시작하셨나요?" 후속 확인 1회 (M14) |
| 5b | 상대가 거절 또는 무응답 | 거절은 통보되지 않는다. 보낸 요청 목록에 "응답 없음"으로 표시. `[P-08]`일 후 만료 |

### Decision Point

- 2단계: 요청을 보낼 것인가. 시스템은 공통 관심사와 메시지 소재를 보여줘 "무슨 말을 하지"의 비용을 줄인다.
- 6a: 지금 메신저로 갈 것인가. 시스템은 "누가, 누구에게" 를 확정해 미루지 않게 한다.

### Success State

- 요청 → 수락 → 연결 성립 화면 → "메신저에서 메시지를 보냈어요" 표시.

### Failure / Exit State

| 상황 | 대응 |
|---|---|
| 요청 횟수 상한 도달 | "오늘 보낼 수 있는 요청을 모두 사용했습니다. 내일 다시" |
| 이미 요청이 진행 중 / 이미 연결됨 | 요청 버튼 없음. 현재 상태 표시 |
| 무응답 만료 | "응답 없음"으로 정리. 재요청은 `[P-07]` 대기 후 |
| 수락됐지만 메신저에서 못 찾음 | 실명이 "이름_캠퍼스_반" 형식이라 동명이인은 구분된다. 그래도 못 찾으면(오타 등) "상대에게 먼저 연락해달라고 요청" 행동 |
| 메신저로 갔지만 대화가 시작되지 않음 | 후속 확인에서 "아니오" → 이유 한 가지 선택(못 찾음/시간 없음/부담). MVP 학습 신호 |

## J3. 요청을 받는 쪽

| 항목 | 내용 |
|---|---|
| User Goal | 누가 왜 보냈는지 빨리 파악하고, 부담 없이 수락 또는 거절하고 싶다 |
| Trigger | 이메일/브라우저/앱 내 알림 "○○님이 연결을 요청했습니다" |
| 왜 별도 Journey인가 | H4(수락)는 이 사람의 경험에 달려 있다. 요청을 보내는 쪽 Journey와 동기가 다르다 |

### 흐름

| 단계 | User Action | System Response |
|---|---|---|
| 1 | 알림 확인 | 알림에 보낸 사람 표시명, 공통 관심사 개수와 이름, 메시지 첫 줄 포함. 앱을 열기 전에 판단 가능 |
| 2 | 알림 클릭 | 한 번에 해당 요청 화면 도착. 보낸 사람 프로필 요약, 공통 관심사, 메시지 전문 |
| 3 | (선택) 보낸 사람 프로필과 관심사 확인, 그래프에서 위치 확인 | Person Focus로 그 사람과 나의 공통 관심사가 강조된다 |
| 4a | 수락 | 닉네임 사용자라면 "수락하면 내 실명이 상대에게 공개됩니다" 확인. 수락 즉시 연결 성립 화면: 상대 실명, "○○님이 먼저 연락할 예정입니다" |
| 5a | 대기 또는 먼저 연락 | 시작자는 상대지만 먼저 연락해도 된다. `[P-11]`일 후 상대 시작 표시가 없으면 "먼저 연락해도 좋습니다" 안내 |
| 4b | 거절 | 확인 없이 즉시 목록에서 사라짐(5초 되돌리기). "상대에게 알려지지 않습니다"가 버튼 옆에 상시 표시. 같은 사람의 재요청은 `[P-07]` 동안 불가 |
| 4c | 무시 | `[P-08]`일 후 만료. 만료 전 한 번 리마인드 |

### Decision Point

- 4단계: 수락/거절/무시. 시스템은 판단 근거(공통 관심사, 메시지, 프로필)를 한 화면에 모으고, 거절의 심리적 비용을 낮춘다(비통보).

### Success State

- 알림 → 요청 화면 → 수락 → 연결 성립 화면 확인.

### Failure / Exit State

| 상황 | 대응 |
|---|---|
| 알림이 도착하지 않음 (이메일 미확인, 브라우저 미허용) | 앱 내 알림함에 누적. 만료 전 리마인드 1회. 근본 대응은 채널 다양화(S3a) |
| 메시지가 부적절 | 거절 + 신고(S5) 경로 |
| 누군지 모르겠어서 판단 불가 (닉네임 사용자) | 프로필과 관심사, 글로 판단하도록 안내. 그래도 불안하면 무시 가능. OQ-11의 관찰 지점 |

## J4. Similar People

| 항목 | 내용 |
|---|---|
| User Goal | 내가 직접 찾지 않아도 나와 비슷한 사람을 이유와 함께 보고 싶다 |
| Trigger | 온보딩 직후 / 그래프 상단의 "나와 비슷한 사람 보기" / 주간 묶음 알림 "새로운 비슷한 사람 N명" |

### 흐름

| 단계 | User Action | System Response |
|---|---|---|
| 1 | "나와 비슷한 사람 보기" 클릭 | Similar 모드: 나와 공통 관심사 `[P-03]`개 이상인 사람에게 선(Similarity Edge)이 그어지고 선 위에 개수. 나머지 흐림. 사이드 패널에 추천 목록(개수 내림차순, 동점은 희소 관심사 우선) |
| 2 | 목록 또는 선 훑기 | 각 항목에 표시명, 공통 개수, 공통 관심사 이름 전부. "이 선은 관심사가 겹친다는 뜻이며 아는 사이가 아닙니다" 안내 |
| 3 | 선 hover / 사람 클릭 | 그 사람과 나 사이 공통 관심사만 추가 강조. 패널에 그 사람 카드와 "연결 요청" |
| 4 | 요청 | J2로 이어짐. 모드는 유지되어 다른 사람도 이어서 볼 수 있음 |
| 5 | 모드 끄기 / 배경 클릭 | 선이 사라지고 기본 그래프로 복귀 |

### Decision Point

- 2~3단계: 누구에게 요청할 것인가. 시스템은 개수뿐 아니라 "무엇이 겹치는지"를 보여줘 "이야기할 거리가 있는가"를 판단하게 한다.

### Success State

- 추천 목록에서 최소 한 명의 상세를 열고, 요청 여부를 결정했다.

### Failure / Exit State

| 상황 | 대응 |
|---|---|
| 추천 0명 | "아직 공통 관심사가 충분한 사람이 없습니다." 관심사를 더 고르는 진입점 + "새로운 사람이 생기면 알려드립니다" |
| 추천이 너무 많음 | 상위 N명만 그래프에, 나머지는 목록에서 이어 봄 |
| 추천된 사람 대부분에게 이미 요청함 / 연결됨 | 해당 사람은 별도 표시(연결됨/요청 중)로 구분. 새 사람이 없으면 위 빈 상태 |
| 같은 사람이 계속 추천됨 | Later(L9). MVP에서는 관찰만 |

## J5. Network Discovery (S2, 데이터 게이트 통과 시)

| 항목 | 내용 |
|---|---|
| User Goal | 1:1은 부담스럽다. 나와 비슷한 사람들 몇 명과 함께 가볍게 시작하고 싶다 |
| Trigger | 그래프 상단 "추천 네트워크" / 알림 "새 네트워크 추천" |

### 흐름

| 단계 | User Action | System Response |
|---|---|---|
| 1 | 추천 네트워크 목록 확인 | 각 카드: 멤버 수, 멤버 표시명, 전원 공통 관심사 `[P-04]`개 이상, "왜 묶였는지" 한 줄 |
| 2 | 카드 클릭 → "이 네트워크 보기" | Network 모드: 허브 노드 하나에 멤버가 선으로 연결. 멤버 간 선과 멤버–관심사 선은 없음(06 §1.2). 패널에 상세 |
| 3 | 멤버 각각 확인 (선택) | 멤버를 누르면 Person Profile. 돌아오면 Network 모드 유지 |
| 4a | "연결하기(참여)" 클릭 | "참여 의사를 표시했습니다. `[P-09]`명 이상 참여하면 성립됩니다. 현재 N명." 가장 먼저 누른 사람은 성립 시 시작자가 됨을 안내 |
| 4b | 거절 | 이 네트워크는 내 목록에서 사라지고 나 없이 성립될 수 있음. 상대들에게 통보 없음 |
| 4c | 보류 | `[P-10]`일 내 결정. 만료 전 리마인드 |
| 5 | 성립 (`[P-09]`명 이상 참여) | 전원에게 알림. 성립 화면: 참여 멤버 실명, 공통 관심사, **Action 안내**: "주영님이 사내 메신저에서 김민수님, 이지수님을 초대해 대화를 시작해주세요." 실명 목록 복사. 나머지에게는 "주영님이 초대할 예정입니다" |
| 6 | 시작자가 메신저에서 그룹 대화 개설 | 서비스 밖. "초대했어요" 표시 |
| 7 | `[P-11]`일 후 시작 표시 없으면 | 나머지 멤버에게 "누구든 먼저 초대해도 좋습니다" |
| 8 | 후속 확인 | "네트워크 대화가 시작되었나요?" 1회 |

### Decision Point

- 4단계: 참여할 것인가. 시스템은 "누구와, 왜, 무엇을 공유하는지"를 한 카드에 담는다. 시작자 부담을 알리되 참여를 막지 않도록 "먼저 참여하면 시작자가 됩니다"는 안내 톤을 유지한다(OQ-12 관찰).

### Success State

- 참여 → 성립 → 시작자가 메신저 그룹 개설 → "초대했어요" 표시.

### Failure / Exit State

| 상황 | 대응 |
|---|---|
| 추천 후보 0개 (게이트 미통과) | 기능 자체가 노출되지 않음. 운영자만 후보 수 확인 |
| 후보는 있으나 나에게 해당 없음 | "아직 나에게 맞는 네트워크가 없습니다. 관심사를 더 고르면 생길 수 있습니다" |
| 참여했지만 인원 미달로 만료 | "참여 인원이 부족해 성립되지 않았습니다." 참여한 사람끼리는 1:1 요청 진입점 제공 |
| 성립됐지만 시작자가 움직이지 않음 | 7단계 재안내. 그래도 없으면 후속 확인에서 학습 |

## J6. 재방문 (알림에서 시작하는 흐름)

| 항목 | 내용 |
|---|---|
| User Goal | 나에게 온 것을 빠르게 처리하고 싶다 |
| Trigger | 이메일 / 브라우저 알림 / (S3a) 등록 채널 알림 |
| 왜 별도 Journey인가 | H9. 재방문의 주된 동력은 "나에게 온 것"이다. 이 흐름이 짧지 않으면 재방문이 끊긴다 |

### 흐름

| 알림 종류 | 도착 화면 | 기대 행동 |
|---|---|---|
| 연결 요청 도착 | 해당 요청 화면 (J3-2) | 수락/거절 |
| 요청 수락됨 | 연결 성립 화면 (J2-6a) | 메신저로 이동 |
| Network 성립 | Network 성립 화면 (J5-5) | 초대 / 대기 |
| 시작자 재안내 | 연결 성립 화면 | 메신저로 이동 |
| 후속 확인 | 한 질문 화면 | 예/아니오 |
| 주간 묶음 (S3) | Similar People 모드 / 관심사 상세 | 탐색 |

### Success State

- 알림 클릭 후 한 화면 안에서 기대 행동을 완료했다.

### Failure / Exit State

| 상황 | 대응 |
|---|---|
| 로그인이 풀려 있음 | 로그인 후 원래 목적지로 자동 이동 |
| 알림 대상이 이미 처리됨 (만료, 취소) | "이미 처리된 요청입니다"와 함께 받은 요청 목록으로 |

## Step 3 결정 사항 / 미결정 사항 (Journey)

### 결정됨

- 요청을 받는 쪽(J3)과 재방문(J6)을 별도 Journey로 둔다. H4와 H9가 여기에 달려 있다.
- 온보딩에서 "실명은 연결 성립 시에만 공개"를 첫 화면과 실명 입력 시점, 수락 시점 세 번 안내한다.
- 거절은 상대에게 통보하지 않는다. 무응답은 만료 전 리마인드 1회.
- 수락 직후 화면이 곧 연결 성립 화면이며 Action 안내를 포함한다. 별도 단계를 두지 않는다.
- Network 성립 실패 시 참여자끼리 1:1 요청 진입점을 제공한다.
- 후속 확인은 "예/아니오 + 아니오 시 이유 한 가지"까지만.
