## 1. 그래프 설계 결정 (Step 1~3에서 미뤄온 것)

### 1.1 기본 그래프의 범위 (OQ-1 결정)

전체 조직을 그리지 않는다. 그래프에는 항상 **앵커(중심)**가 있고, 앵커에서 두 단계까지만 보여준다.

**앵커 = 나 (기본)**

| 계층 | 내용 | 상한 |
|---|---|---|
| 0 | 나 | 1 |
| 1 | 내 관심사 전부 | `[P-02]` (최대 15) |
| 2 | 내 관심사를 가진 사람 중 나와 공통 관심사가 많은 순 상위. 단, 내 관심사마다 최소 2명은 포함되도록 보정 | `[P-13]` 30명 |
| 3 | 표시된 사람들이 가진 관심사 중 내가 갖지 않은 것. 표시된 사람 중 가진 사람이 많은 순 | `[P-14]` 8개 |

- 사람 노드는 표시된 관심사 노드에만 선으로 연결된다. 표시되지 않은 관심사와의 관계는 그리지 않는다.
- 계층 3(인접 관심사)이 있는 이유는 H7이다. "내가 고르지 않았지만 나와 비슷한 사람들이 많이 가진 관심사"를 발견하는 것이 그래프여야 하는 이유다.
- 상한을 넘어 잘린 사람은 패널에서 "N명 더 보기"로 이어 본다.

**앵커 = 관심사 (재중심)**

Interest 상세 패널의 "이 관심사를 중심으로 보기"를 누르면 앵커가 그 관심사로 바뀐다.

| 계층 | 내용 | 상한 |
|---|---|---|
| 0 | 해당 관심사 | 1 |
| 1 | 그 관심사를 가진 사람. 나와 공통 관심사가 많은 순 | `[P-13]` 30명 |
| 2 | 표시된 사람들의 다른 관심사. 가진 사람 많은 순 | `[P-14]` 8개 |

- 나는 앵커가 관심사여도 항상 그래프에 남는다(내가 그 관심사를 갖지 않아도). 나와의 관계를 잃지 않기 위해서다.
- "내 그래프로 돌아가기"가 항상 보인다.
- 사람은 앵커가 되지 않는다. 특정 사람 주변을 파고드는 것은 Non-Goal(아는 사람 찾기)과 가깝다. 사람에 대한 이해는 Person Focus와 Profile로 충분하다.

**Person Focus 시 임시 확장**: 사람을 선택하면 그 사람의 관심사 중 그래프에 없던 것이 임시로 나타난다(≤15개). 선택을 해제하면 사라진다. "이 사람이 무엇에 관심 있는지"를 그래프에서 온전히 보여주기 위해서다.

### 1.2 Network 모드의 선 표현 (Phase 0 피드백 반영)

Phase 0에서 멤버–관심사 선과 멤버–멤버 선을 모두 그려 가독성이 떨어졌다. 4명 × 5개 관심사면 선이 26개였다.

**결정: 네트워크 허브 노드**

- 네트워크 하나를 **허브 노드** 하나로 표현한다. 허브는 관심사 노드와 다른 모양이며, 안쪽 또는 곁에 전원 공통 관심사가 이름으로 적힌다.
- 멤버는 허브에 선 하나로 연결된다. 멤버 4명이면 선 4개.
- 멤버–멤버 선과 멤버–관심사 선은 그리지 않는다. 개별 관심사 노드는 흐려진다.
- 허브를 가리키면 공통 관심사 노드들이 잠시 강조되어 "이 관심사들의 교집합"임을 보여준다.

이유: Network의 의미는 "이 사람들이 하나의 그룹 후보"라는 것이지 "누가 누구와 어떤 관심사로 연결되는가"가 아니다. 그룹을 하나의 점으로 만들면 의미가 정확해지고 선은 멤버 수만큼만 남는다. 1:1 Similarity Edge는 그대로 사람–사람 선으로 두어 두 개념이 시각적으로 구분된다.

### 1.3 Similar 모드의 상한

- 그래프에는 공통 관심사 개수 상위 `[P-15]` 10명까지만 선을 그린다. 나머지는 패널 목록에서 본다.
- 목록의 사람을 누르면 그 사람이 그래프에 없더라도 임시로 나타나 선이 그어진다.

## 2. 그래프 시각 부호화 원칙

디자인 세부는 자유지만 다음은 구분되어야 한다.

| 구분 대상 | 요구 |
|---|---|
| 나 / 다른 사람 / 관심사 / 네트워크 허브 | 네 종류가 한눈에 다르게 보여야 한다. 관심사는 사람보다 크고 이름이 항상 보인다 |
| 관심사의 Category | 같은 Category는 같은 색 계열. 범례 제공 |
| 실명 표시명 / 닉네임 표시명 | 사람 노드 또는 이름 옆에 실명 사용자 표시 |
| 연결 상태 | 연결된 사람, 요청 진행 중인 사람은 노드에 표시가 있어야 한다. 추천에서 이미 처리한 사람을 구분하기 위해 |
| 강조 / 흐림 / 선택 | 어떤 모드에서든 "지금 중요한 것"과 "배경"이 구분되고, "선택한 것" 하나는 더 강하게 |
| 내 관심사 / 인접 관심사 | 내가 고른 관심사와 계층 3의 인접 관심사가 구분되어야 한다(예: 테두리) |
| 소속 관계 선 / Similarity Edge / 허브 선 | 세 종류의 선이 다르게 보여야 한다. Similarity Edge에는 숫자 배지 |
| 잘림 안내 | 상한으로 잘린 것이 있으면 그래프 구석에 "N명 더 있음"이 보인다 |

레이블: 사람 이름은 확대 수준에 따라 숨길 수 있지만, 강조된 사람의 이름은 항상 보인다.

## 3. 화면별 요구사항

### 3.1 Onboarding

**3.1.1 초대 / 소개**

- 보이는 것: 서비스 세 문장 설명. 공개 범위 요약 한 줄("연결 전에는 표시명과 관심사만, 연결되면 실명"). 로그인 버튼.
- 초대 링크가 없으면: "초대 링크가 필요합니다" 화면만.

**3.1.2 로그인**

- 보이는 것: 지원하는 계정 버튼들. 무엇을 가져오는지(이메일, 이름) 안내.
- 실패: "로그인에 실패했습니다. 다시 시도" 외에 다른 경로 없음.

**3.1.3 실명 · 표시명**

- 실명 입력: 이름과 반을 따로 입력. 화면에 조합 결과를 미리 보여준다(예: "최준환_서울_18반"). 안내 문구 "사내 메신저에 표시되는 이름과 같아야 합니다. 연결이 성립될 때 상대에게 공개됩니다." 캠퍼스는 단일이므로 고정.
- 표시명 선택: 두 가지 선택지가 같은 크기로. 각 선택지 아래에 결과 설명.
  - 닉네임: "연결 전에는 닉네임만 보입니다. 수락하면 실명이 공개됩니다."
  - 실명: "처음부터 실명이 보입니다. 실명 표시가 붙습니다."
- 닉네임 입력 시 실시간 검사: 중복, 실명 유사(12_PRIVACY 규칙), 부적절 표현.
- "나중에 바꿀 수 있습니다" 안내.

**3.1.4 관심사 선택** (My Profile 관심사 수정과 같은 화면)

- 구성: 상단에 검색 입력과 선택 현황("7개 선택 · 최소 5 · 최대 15"). 본문은 Category별 섹션이 세로로 이어지는 하나의 목록. Category 이름을 누르면 해당 섹션으로 이동. 선택한 관심사는 상단에 칩으로 고정 표시되어 스크롤해도 보인다.
- Category 탭으로 나누지 않는 이유: 100개는 한 목록으로 훑을 수 있는 크기이고, 탭은 "다른 Category에 뭐가 있는지"를 숨긴다.
- 각 관심사 항목: 이름, 가진 사람 수(예: "42명"). 사람 수는 "여기 고르면 누가 있을지"의 힌트다.
- 최소 미만: 완료 버튼 비활성 + "N개 더 고르면 추천이 생길 가능성이 높아집니다".
- 최대 도달: 추가 선택 불가 + "최대 15개까지 고를 수 있습니다. 정말 중요한 것만 남겨보세요".
- 원하는 것이 없음: 목록 끝과 검색 결과 없음 상태에 "관심사 제안하기".

**3.1.5 알림 설정**

- 보이는 것: "요청이 오면 어디로 알려드릴까요?" 이메일(기본 켜짐, 주소 표시), 브라우저 알림(허용 버튼, 설명: "브라우저가 열려 있으면 바로 알려드립니다"), (S3a) 외부 채널 등록.
- 브라우저 알림 거부해도 진행 가능. "설정에서 다시 켤 수 있습니다".

### 3.2 Graph (홈)

**보이는 것**

- 그래프 영역: 1.1의 범위대로. 범례(나/사람/관심사/허브, Category 색, 실명 표시, 연결 상태 표시).
- 상단: 앵커 표시("내 그래프" 또는 "#백엔드 중심"), "나와 비슷한 사람 보기" 토글, "추천 네트워크" 토글(S2), "내 그래프로 돌아가기"(앵커가 관심사일 때).
- 사이드 패널: 상태에 따라 4종.
- 구석: 잘림 안내, 확대/축소/맞춤 버튼.

**할 수 있는 것**: 07_INTERACTION_SPEC 참조.

**상태별 요구**

| 상태 | 그래프 | 패널 |
|---|---|---|
| 아무것도 선택 안 함 | 전체가 기본 강조 | 기본 패널: 범례, "사람이나 관심사를 눌러보세요", Similar 진입 버튼, 추천 네트워크 요약(S2), 처리할 알림 요약 |
| Person 선택 | 그 사람 + 그 사람의 관심사(임시 확장 포함)만 강조. 공통 관심사는 더 강하게. 나머지 흐림 | Person Profile |
| Interest 선택 | 그 관심사 + 가진 사람만 강조. 사람이 상한 초과면 공통 많은 순 상위 | Interest 상세 |
| Similar 모드 | 나 + 상위 10명 + Similarity Edge(숫자). 나머지 흐림 | Similar 목록 |
| Similar 모드 + 사람 선택 | 위에 더해 그 사람과 나의 공통 관심사 강조, 그 Edge 굵게 | Similar 목록 상단에 그 사람 카드 |
| Network 모드 (S2) | 허브 + 멤버 + 허브 선. 나머지 흐림 | Network 상세 |
| 앵커 = 관심사 | 1.1 표대로 재구성. 나는 남아 있음 | Interest 상세 |

**첫 진입 (온보딩 직후)**: 기본 상태 + 한 번만 보이는 안내 3개(관심사 누르기, 사람 누르기, 비슷한 사람 보기). 닫으면 다시 나오지 않는다.

### 3.3 패널: Interest 상세

- 머리: 관심사 이름, Category, 가진 사람 수, "내 관심사" 표시(내가 가졌으면), "이 관심사를 중심으로 보기" 버튼.
- 사람 목록: 표시명(실명 표시), 나와 공통 개수, 연결 상태. 공통 많은 순. 상한 20개씩 "더 보기".
- 최근 글(S1): 최신 5개. 작성자 표시명, 시간, 내용. "글 남기기" 버튼(내가 이 관심사를 가진 경우만. 아니면 "이 관심사를 추가하면 글을 남길 수 있습니다").
- 내가 가진 관심사가 아니면 "내 관심사에 추가" 버튼. 추가 즉시 그래프 갱신.

### 3.4 패널: Person Profile

- 머리: 표시명(실명 표시), 연결 상태 배지. 연결됨이면 실명도.
- 관심사: 전체 목록. 공통은 앞에 모아 구분 표시. "공통 관심사 N개 / 상대 관심사 M개".
- 최근 글(S1): 최신 3개.
- 행동 영역(상태별로 하나만):

| 상태 | 보이는 행동 |
|---|---|
| 관계 없음 | "연결 요청" (남은 횟수 표시) |
| 요청 보냄 | "요청 보냄 · 응답 대기" + 취소(S6) |
| 요청 받음 | "수락" / "거절" (요청 상세 Overlay로) |
| 연결됨 | "연결됨" + 성립 화면 열기 |
| 응답 없음(만료/거절) | "응답 없음 · N일 후 다시 요청 가능" |
| 나 자신 | "관심사 수정" |

- 부가: 신고(S5)는 눈에 덜 띄는 위치(더보기 메뉴).

### 3.5 패널: Similar People

- 머리: "나와 비슷한 사람 N명", 기준 설명 "공통 관심사 `[P-03]`개 이상", 안내 "선은 관심사가 겹친다는 뜻이며 아는 사이가 아닙니다".
- 목록: 표시명(실명 표시), 공통 개수, 공통 관심사 이름 전부(칩), 연결 상태. 개수 내림차순, 동점은 희소 우선. 그래프에 그려진 상위 10명은 표시로 구분.
- 사람 선택 시 상단에 카드: 표시명, 공통 관심사, "연결 요청".
- 이미 연결/요청 중인 사람은 목록에 남되 흐리게 + 상태 표시. 새 사람만 보기 토글.
- 모드 끄기 버튼.

### 3.6 패널: Network 상세 (S2)

- 머리: "추천 네트워크", 멤버 수, "이 N명은 관심사 K개를 모두 공유합니다".
- 공통 관심사 칩 전부.
- 멤버 목록: 표시명, 참여 상태(참여/미정). 거절한 사람은 보이지 않음.
- 참여 현황: "현재 2명 참여 · 3명이 되면 성립 · 2일 남음".
- 행동: "연결하기(참여)" / "거절". 참여 전 안내 "가장 먼저 참여한 사람이 성립 시 대화를 시작하는 역할을 맡습니다".
- 참여 후: "참여 의사를 표시했습니다" + 현황.

### 3.7 Connections

- 탭 배지: 받은 요청 수.
- 받은 요청 항목: 표시명(실명 표시), 공통 개수, 메시지 첫 줄, 남은 기간. 누르면 요청 상세 Overlay.
- 보낸 요청 항목: 표시명, 보낸 날짜, 상태(대기 / 응답 없음 / 만료 / 취소됨). 대기 중이면 취소(S6).
- 연결됨 항목: 실명, 공통 관심사 칩, 성립 날짜, 시작자 표시("내가 먼저" / "상대가 먼저"), 대화 시작 여부. 누르면 연결 성립 Overlay.

### 3.8 Networks (S2)

- 추천: 카드(멤버 표시명, 공통 관심사, 참여 현황, 남은 기간). 누르면 Graph의 Network 모드.
- 참여 대기: 내가 참여한 것. 현황 강조.
- 성립됨: 멤버 실명, 공통 관심사, 시작자, 초대 여부. 누르면 Network 성립 Overlay.

### 3.9 Notifications

- 항목: 종류 아이콘, 한 줄 요약(누가, 무엇을, 판단 근거), 시간, 처리 여부.
- 처리 필요한 것(받은 요청, 성립)은 상단 고정.
- 전역 내비 배지 규칙: **처리가 필요한 것의 수**(받은 요청 + 확인 안 한 성립 + 후속 확인). 단순 미읽음 수가 아니다. 배지가 0이면 할 일이 없다는 뜻이어야 한다.

### 3.10 My Profile

- 남에게 보이는 모습 미리보기 두 가지: "연결 전" / "연결 후". 표시명 선택의 결과를 여기서 실감한다.
- 관심사 수정 → 3.1.4 화면. 저장 시 "그래프와 추천이 바뀝니다".
- 표시명 변경(닉네임 ↔ 실명). 변경 시 진행 중인 요청의 상대에게는 새 표시명이 보인다는 안내.
- 실명 수정.
- 내가 쓴 글(S1) 목록과 삭제.

### 3.11 Settings

- 알림: 채널별 토글(이메일, 브라우저, 외부 채널 S3a). 종류별(즉시 / 주간 묶음). 받은 요청 알림을 모든 채널에서 끄려 하면 막고 이유 안내.
- 계정: 로그인 계정 정보, 탈퇴(탈퇴 시 그래프·요청·연결·글 모두 제거 안내).

### 3.12 Overlay

**연결 요청 작성**

- 상대 표시명, 공통 관심사 칩(메시지 소재).
- 메시지 입력(필수, 상한 `[P-16]` 200자 가정). 자리 표시 문구: "어떤 이야기를 나누고 싶은지 한두 문장이면 충분합니다."
- 안내: "상대가 수락하면 서로 실명이 공개됩니다."
- 남은 요청 횟수.
- 보내기 / 취소.

**요청 상세 (받은 요청)**

- 보낸 사람 표시명(실명 표시), 관심사 전체(공통 구분), 공통 개수, 메시지 전문, 받은 날짜, 남은 기간.
- "그래프에서 보기" → Graph Person Focus.
- 수락 / 거절 / 신고. 닉네임 사용자의 수락 버튼 옆: "수락하면 내 실명이 공개됩니다". 거절 옆: "상대에게 알려지지 않습니다".

**연결 성립**

- 제목: "연결되었습니다".
- 상대 실명(크게), 공통 관심사 칩, 요청 메시지 원문.
- **Action 안내 (가장 눈에 띄게)**:
  - 시작자(요청 보낸 사람)에게: "○○님, 사내 메신저에서 **김지수**님을 찾아 첫 메시지를 보내주세요." 실명 복사 버튼. 메신저 링크(가능 시).
  - 상대에게: "○○님이 먼저 연락할 예정입니다. 먼저 연락하셔도 좋습니다."
- 버튼: "메신저에서 메시지를 보냈어요" (시작자) / "연락을 받았어요" (상대). 누르면 대화 시작으로 기록.
- 첫 메시지 소재: 공통 관심사와 상대의 최근 글(S1). 문안은 써주지 않는다.

**Network 성립 (S2)**

- 제목: "네트워크가 성립되었습니다".
- 멤버 실명 목록(전체 복사 버튼), 공통 관심사 칩.
- Action 안내: 시작자에게 "주영님이 사내 메신저에서 김민수님, 이지수님을 초대해 대화를 시작해주세요." 나머지에게 "주영님이 초대할 예정입니다."
- 버튼: "초대했어요" (시작자) / "초대받았어요" (나머지).

**후속 확인**

- 한 질문: "김지수님과 대화를 시작하셨나요?" 예 / 아니오.
- 아니오 → 이유 하나: 메신저에서 찾지 못함 / 아직 시간이 없었음 / 막상 부담스러움 / 기타.
- "찾지 못함"이면 상대에게 "먼저 연락해달라"는 알림을 보낼지 묻는다(OQ-13 관련).

**글 작성 (S1)**: 관심사 이름, 입력(상한 `[P-17]` 300자 가정), 안내 "댓글은 없습니다. 관심 있는 사람이 프로필로 찾아옵니다."

**관심사 제안 (S4)**: 이름 입력, 입력 중 비슷한 기존 관심사 제시("혹시 이것인가요?"), 제출 후 "운영자가 확인합니다".

**신고 (S5)**: 대상(사람/요청/글), 사유 선택, 설명(선택), 제출 후 "운영자가 확인합니다".

## 5. 모바일 범위

- 그래프는 제공하지 않는다. 모바일에서 Graph에 오면 "그래프는 PC에서 볼 수 있습니다" + Connections, Notifications 진입점.
- 제공: Connections(3탭), Notifications, Overlay 요청 상세 / 연결 성립 / Network 성립 / 후속 확인, Settings 알림.
- 목적은 하나다. 알림을 받고 그 자리에서 수락/거절과 성립 확인을 할 수 있게 한다.

## Step 4 결정 사항 / 미결정 사항 (Screen)

### 결정됨

- 기본 그래프 = 나 + 내 관심사 + 사람 30명(관심사당 최소 2명 보정) + 인접 관심사 8개. 앵커를 관심사로 옮길 수 있고, 사람은 앵커가 되지 않는다.
- Person Focus 시 그 사람의 관심사가 임시로 모두 나타난다.
- Network 모드는 허브 노드 하나 + 멤버 선. 멤버 간 선과 멤버–관심사 선은 그리지 않는다.
- Similar 모드 그래프 선은 상위 10명. 나머지는 목록.
- 온보딩 관심사 선택은 탭이 아닌 Category 섹션이 이어진 한 목록 + 검색 + 선택 칩 고정.
- 알림 배지 = 처리가 필요한 것의 수.
- 성립 화면 버튼 문구: 시작자 "메신저에서 메시지를 보냈어요", 상대 "연락을 받았어요". Network는 "초대했어요" / "초대받았어요".
- 거절과 만료는 보낸 쪽에 "응답 없음"으로 동일하게 보인다.
- 모바일은 요청 처리와 성립 확인만.
