# 13. Recommendation Explainability Principles

| 항목 | 내용 |
|---|---|
| 문서 상태 | Draft v0.1 (Step 5) |
| 작성일 | 2026-09-07 |
| 선행 문서 | 02_PRD (FR-7, FR-12, NFR-1), 08_INTEREST_POLICY (§6) |

이 문서는 "왜 이 사람(그룹)이 나에게 보이는가"를 사용자가 항상 이해할 수 있게 하는 원칙과, 그 원칙을 지키면서 추천을 정렬하는 규칙을 정한다. 알고리즘 구현은 다루지 않는다.

---

## 1. 다섯 가지 원칙

| # | 원칙 | 뜻 |
|---|---|---|
| 1 | **이유 없는 추천은 없다** | 화면에 사람이나 그룹이 "추천"으로 나타나면 그 옆에 반드시 이유가 있다. 이유를 표시할 수 없는 추천은 만들지 않는다 |
| 2 | **이유는 사용자의 언어다** | 이유는 관심사 이름과 개수다. 점수, 유사도, 퍼센트를 보여주지 않는다. "87% 일치"는 사용자가 검증할 수 없다. "#축구 #백엔드 #OSS 3개"는 검증할 수 있다 |
| 3 | **이유는 완전하다** | 공통 관심사 개수만이 아니라 이름을 전부 보여준다. "5개 중 3개"처럼 일부만 보여주지 않는다 |
| 4 | **정렬 기준도 설명한다** | 목록 상단에 "공통 관심사가 많은 순, 같으면 드문 관심사를 공유하는 순"이 적혀 있다. 사용자가 순서를 예측할 수 있어야 한다 |
| 5 | **추천은 추천일 뿐이다** | 추천은 "관심사가 겹친다"는 사실이지 "잘 맞을 것"이라는 판단이 아니다. 문구는 "비슷한 사람", "관심사가 겹치는 사람"이며 "당신에게 맞는", "추천 상대"는 쓰지 않는다 |

---

## 2. 문구 규칙

| Bad | Good | 왜 |
|---|---|---|
| "민수님을 추천합니다" | "민수님과 공통 관심사 4개: #축구 #백엔드 #OSS #독서" | 이유가 있다 |
| "일치도 87%" | "공통 관심사 4개 / 상대 관심사 7개" | 검증 가능하다 |
| "당신과 잘 맞는 사람" | "나와 관심사가 겹치는 사람" | 판단이 아니라 사실 |
| "추천 네트워크" (단독) | "이 4명은 관심사 5개를 모두 공유합니다: #백엔드 #OSS #축구 #독서 #러닝" | 그룹 이유가 완전하다 |
| "AI가 분석한 결과" | (쓰지 않음) | 블랙박스를 암시한다 |
| "인기 있는 사람" | (쓰지 않음) | 인기 지표 없음 |
| 사람–사람 선 (설명 없음) | "선은 관심사가 겹친다는 뜻입니다. 아는 사이가 아닙니다" | 오해 방지 (FR-8.3) |

## 3. Similar People 정렬 규칙

### 3.1 기준

| 순위 | 기준 | 설명 |
|---|---|---|
| 1차 | **공통 관심사 개수** 내림차순 | 사용자가 가장 먼저 이해하는 기준 |
| 2차 (동점) | **희소성 가중 합** 내림차순 | 같은 3개라도 "#클라이밍 #보드게임 #OSS"가 "#백엔드 #알고리즘 #취업준비"보다 앞선다 |
| 3차 (동점) | 최근 가입 순 | 새로 온 사람에게 노출 기회 |

### 3.2 희소성 가중 (제품 관점 정의)

- 관심사마다 "가진 사람이 적을수록 큰" 무게를 둔다. 전체의 절반이 가진 관심사는 무게가 작고, 20명이 가진 관심사는 무게가 크다.
- 무게는 **정렬에만** 쓴다. 화면에 무게나 점수를 보여주지 않는다. 사용자에게는 "드문 관심사를 공유하는 순"이라는 말로 설명한다.
- 왜 2차인가: 1차로 두면 "공통 2개(희소)"가 "공통 4개(인기)"보다 앞서는 순간 사용자가 순서를 이해하지 못한다. 개수가 먼저고, 희소성은 동점 처리다.
- Popular Interest Bias 대응은 이 가중과 08 §6의 세분화 두 가지로 한다. 인기 관심사를 공통 개수에서 빼지는 않는다. 뺀 순간 "왜 #백엔드는 안 세요?"를 설명할 수 없다.

### 3.3 임계값 P-03

| 파라미터 | 값 | 왜 | 너무 높으면 | 너무 낮으면 | 조정 데이터 |
|---|---|---|---|---|---|
| P-03 공통 관심사 기준 | **3** | 최소 5개를 고른 사람끼리 3개가 겹치면 절반 이상이다. 우연이 아니다 | 추천 0명이 대다수 | 1~2개 겹침은 대부분 인기 관심사라 의미 없음 | 추천 0명 비율(목표 < 20%), 평균 추천 수, 추천 개수별 요청 전환율 |

- 3에서 시작하되, 공개 3일째에 추천 0명 비율이 30%를 넘으면 2로 낮추고, 낮춘 뒤에는 목록에 "공통 관심사 2개인 사람은 드문 관심사를 공유할 때만" 규칙을 추가한다(2개 중 하나 이상이 희소 관심사).

### 3.4 제외와 구분

| 대상 | 처리 |
|---|---|
| 요청 권한 정지된 사용자 | 제외 |
| 온보딩 미완료 | 제외 |
| 내가 거절한 사람 | 숨김 ("숨긴 사람 보기"로 복구) |
| 나를 거절한 사람 (응답 없음) | 남김. "응답 없음 · N일 후 재요청" 표시 |
| 이미 연결됨 | 남김. "연결됨" 표시. "새 사람만 보기" 토글로 제외 가능 |
| 요청 진행 중 | 남김. 상태 표시 |

이미 처리한 사람을 목록에서 없애지 않는 이유는 "왜 이 사람이 사라졌지?"가 곧 설명 불가능한 추천이기 때문이다. 상태와 함께 남기고 사용자가 필터한다.

### 3.5 갱신

- 관심사 변경, 신규 가입, 상태 변화 즉시 반영. 목록을 열 때마다 현재 기준.
- 순서가 자주 바뀌어 혼란스럽다는 피드백이 있으면 "오늘 기준" 고정 검토(Later).

## 4. Network 설명 규칙

| 규칙 | 내용 |
|---|---|
| 이유 문장 | "이 N명은 관심사 K개를 모두 공유합니다" + 관심사 이름 전부 |
| 왜 교집합인가의 설명 | 카드에 "모두" 강조. 교집합이어야 이 한 문장으로 설명이 끝난다 |
| 멤버 표시 | 표시명과, 각 멤버가 나와 겹치는 관심사 개수(전원 공통 외에 추가로) |
| 순서 (여러 추천) | 전원 공통 관심사 개수 → 희소성 가중 → 멤버 수 적은 순(작은 그룹이 성립 쉬움) |
| 시작자 안내 | "가장 먼저 참여한 사람이 대화를 시작하는 역할" |

## 5. 그래프에서의 설명

| 요소 | 설명 방식 |
|---|---|
| Similarity Edge | 숫자 배지 = 공통 개수. hover에 이름 전부. 범례에 "관심사가 겹친다는 뜻" |
| 그래프에 보이는 사람 (기본 앵커) | 기본 패널에 "나와 공통 관심사가 많은 30명이 보입니다. N명 더 있음" |
| 인접 관심사 (계층 3) | hover에 "내 그래프의 사람 M명이 가진 관심사". 왜 나타났는지 설명 |
| Network 허브 | hover에 교집합 관심사 강조 + "이 N명이 모두 가진 관심사 K개" |
| 잘림 | "N명 더 있음"은 항상 보인다. 사용자는 그래프가 전부가 아님을 안다 |

## 6. 하지 않는 것

| 하지 않음 | 이유 |
|---|---|
| 협업 필터링, 임베딩 유사도 등 설명 불가능한 점수 | 원칙 1, 2 위반. MVP는 공통 관심사만으로 H2를 검증한다 |
| 활동 기반 가중(접속 빈도, 글 수) | "왜 이 사람이 위에 있지?"를 설명할 수 없다. Later에서도 설명 가능한 형태로만 |
| 수락률 기반 가중(잘 수락하는 사람 우선) | 인기 지표. 관심사 대신 사람을 좇게 한다 |
| 추천 이유 숨기기(요약만 보여주기) | 원칙 3 위반 |
| A/B로 정렬을 몰래 바꾸기 | 원칙 4 위반. 바꾸면 화면의 정렬 설명도 바꾼다 |

## 결정 / 미결정

### 결정됨

- 다섯 원칙. 점수·퍼센트 비노출, 관심사 이름 전부 노출, 정렬 기준 명시.
- 정렬: 공통 개수 → 희소성 가중 → 최근 가입. 희소성은 동점 처리에만.
- P-03=3. 추천 0명 비율 30% 초과 시 2로 낮추되 희소 조건 추가.
- 처리한 사람은 목록에서 없애지 않고 상태와 함께 남긴다.
- 설명 불가능한 점수, 활동·수락률 가중은 쓰지 않는다.

### 미결정

| 항목 | 담당 |
|---|---|
| 희소성 무게의 구체적 형태 | 구현 단계. 단, "가진 사람이 적을수록 큼"이라는 성질만 지키면 됨 |
| "드문 관심사"의 기준(가진 사람 N명 미만) | 공개 후 데이터 |
