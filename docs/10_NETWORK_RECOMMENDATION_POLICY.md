## 1. Network의 정의

> **Network는 "전원이 여러 관심사를 함께 공유하는 3~6명의 그룹 후보"다.** 추천은 후보일 뿐이고, 각자가 참여를 선택해 기준 인원이 모이면 성립한다.

1:1 Connection과의 차이:

| | 1:1 Connection | Network |
|---|---|---|
| 가치 | 깊은 공통점, 직접 대화 | 낮은 부담, 여럿이 시작 |
| 성립 조건 | 한 사람의 수락 | 여러 사람의 참여 |
| 시작자 | 요청 보낸 사람 | 가장 먼저 참여한 사람 |
| 결과 | 두 사람의 실명 공개 | 참여자 전원의 실명 공개 |

1:1이 "이 사람과 이야기하고 싶다"라면 Network는 "이 주제들로 모임을 만들고 싶다"에 가깝다. 두 가치가 실제로 다른지는 H6로 검증한다.

## 2. 후보 생성 규칙

| 규칙 | 내용 |
|---|---|
| 공통 관심사 정의 | **멤버 전원의 교집합.** Pairwise가 아니다 |
| 왜 교집합인가 | "이 N명은 이 K개를 모두 공유합니다"가 유일하게 설명 가능한 이유다. Pairwise는 "A–B는 축구, B–C는 독서"처럼 이유가 흩어져 설명이 불가능하다 |
| 교집합의 한계 | 엄격해서 좋은 그룹을 놓칠 수 있다. 예: 5명 중 1명만 관심사 하나가 빠진 경우. MVP에서는 감수하고, 후보 수가 부족하면 P-04를 낮추는 것으로 대응한다 |
| 후보 크기 | `[P-05]` 3~6명 중 교집합 조건을 만족하는 최대 그룹. 같은 사람들로 이루어진 부분집합은 별도 후보로 만들지 않는다 |
| 한 사람이 받는 추천 수 | 동시에 최대 **3개.** 그 이상은 판단 피로 |
| 제외 | 온보딩 미완료자, 요청 권한이 정지된 사용자 제외 |
| 이미 연결된 사람 | 포함 **가능.** 아는 사람 한 명이 있으면 참여 부담이 낮아진다. 단, **멤버 전원이 이미 서로 연결된 그룹은 제외**(추천할 이유가 없음) |
| 갱신 | §2a 라이프사이클 참조. 후보 풀은 이벤트마다 갱신, 노출된 추천은 스냅샷으로 고정 |

## 2a. 후보 생성과 노출 라이프사이클

핵심 구분: **후보 풀(Pool)**은 실시간으로 바뀌고, **노출된 추천(Exposed)**은 고정된다.

```
[이벤트: 온보딩 완료 / 관심사 변경 / 탈퇴]
        │
        ▼
   후보 풀 갱신 ─── 게이트 미통과 ──▶ 풀만 유지, 노출 없음 (운영자만 후보 수 확인)
        │
        │ 게이트 통과
        ▼
   노출 판단 ──┬── 온보딩 완료 즉시: 새 사용자에게 최선 후보 1개 (다른 멤버에게도 동시 노출)
              └── 하루 2회 배치 (오전 9시, 오후 6시): 빈 슬롯 채움
        │
        ▼
   노출된 추천 (스냅샷: 멤버·공통 관심사 고정, 만료 3일)
        │
        ├── 3명 참여 → 성립 (늦은 참여자는 만료 전까지 추가 참여)
        ├── 만료 시 인원 미달 → 소멸, 참여자에게 1:1 진입점
        └── 멤버 탈퇴로 잔여 인원 < 3 → 조기 소멸, 안내
```

### 후보 풀 갱신 규칙

| 트리거 | 동작 |
|---|---|
| 온보딩 완료 | 새 사용자를 포함하는 후보를 계산해 풀에 추가 |
| 관심사 변경 | 그 사용자가 포함된 **미노출** 후보를 재계산. **노출된** 추천은 건드리지 않는다 |
| 탈퇴 | 모든 후보와 노출된 추천에서 제거. 노출된 추천의 잔여 인원이 3 미만이면 조기 소멸 |
| 성립 | 같은 멤버 집합의 후보를 풀에서 제거 |

### 노출 규칙

| 규칙 | 내용 |
|---|---|
| 슬롯 | 1인당 동시 노출 최대 **3개**. 빈 슬롯이 있을 때만 새로 노출 |
| 노출 단위 | 후보 하나가 노출되면 **멤버 전원**에게 동시에 노출된다. 한 사람만 보는 추천은 없다. 멤버 중 슬롯이 꽉 찬 사람이 있으면 그 후보는 대기 |
| 온보딩 즉시 노출 | 새 사용자를 포함하는 후보 중 최선 1개를 즉시 노출. 이유: 집중 2주 동안 첫 세션에서 네트워크를 보여줘야 한다. 다른 멤버에게는 "새 멤버가 가입해 네트워크가 생겼습니다" 알림 |
| 배치 노출 | 하루 2회. 슬롯이 빈 사람들에게 우선순위 순으로 |
| 우선순위 | 전원 공통 관심사 개수 → 희소성 가중 → 신규 가입자(3일 이내) 포함 여부 → 멤버 수 적은 순 |
| 중복 방지 | 같은 사람에게 멤버가 대부분 겹치는 두 추천을 동시에 노출하지 않는다(§7) |
| 스냅샷 | 노출 시점의 멤버와 공통 관심사가 카드에 고정된다. 이후 멤버가 관심사를 바꿔도 카드는 그대로. "추천 당시 기준"을 카드에 작게 표시 |
| 신규 가입자의 기존 추천 편입 | **없다.** 노출된 추천에 새 사람이 끼어들지 않는다. 새 사람은 새 후보를 만든다 |

### 왜 이 방식인가

- 실시간 노출은 "내가 참여한 그룹의 멤버가 바뀌는" 경험을 만든다. 참여는 특정 사람들에 대한 의사 표시이므로 멤버가 고정되어야 한다.
- 하루 1회 배치는 2주 집중 기간에 너무 느리다. 온보딩 즉시 1개 + 하루 2회로 첫 세션 경험과 안정성을 함께 잡는다.
- 후보 풀 자체는 실시간이어야 가입자가 늘수록 더 좋은 후보가 다음 노출에 반영된다.

### 사용자에게 보이는 타이밍

| 상황 | 사용자가 보는 것 |
|---|---|
| 온보딩 직후 후보 있음 | 그래프 기본 패널에 "추천 네트워크 1개" 즉시 |
| 온보딩 직후 후보 없음 | "관심사가 비슷한 사람이 더 모이면 네트워크를 추천해드립니다" |
| 배치 노출 | 알림 "새 네트워크 추천" (즉시 알림 채널). 앱 열면 카드 |
| 슬롯 3개 모두 사용 중 | 새 추천 없음. 카드에 "결정하면 다른 추천을 볼 수 있습니다" |

## 3. Product Parameter

| 파라미터 | 값 | 왜 이 값인가 | 너무 높으면 | 너무 낮으면 | 조정 데이터 |
|---|---|---|---|---|---|
| **P-04 전원 공통 관심사** | **5** | 3~6명이 5개를 모두 공유하면 "우연"이 아니다. 개발 3개 + 취미 2개 같은 조합이면 대화 주제가 확실하다 | 후보가 거의 없다. 특히 관심사 분포가 고르면 0개 | "백엔드+알고리즘+취업준비" 3개로 묶이는 수백 명 규모 그룹이 생기고, 인기 관심사만으로 구성된 무의미한 그룹이 된다 | 후보 수(게이트), 후보의 공통 관심사 중 인기 관심사(30%+) 비율, 참여율 |
| **P-05 그룹 크기** | **3~6, 우선 3~5** | 3명은 그룹의 최소. 6명을 넘으면 메신저 그룹에서 절반이 침묵한다 | 수동적 참여. 시작자 부담 급증 | 2명이면 1:1과 같다 | 성립된 Network의 크기별 "대화 시작" 비율 |
| **P-09 최소 참여 인원** | **3** | 3명이 참여하면 시작자 + 2명으로 대화가 된다. 전원 참여를 요구하면 성립이 거의 불가능 | 성립률 급락 | 2명이면 1:1 | 후보당 참여자 수 분포, 성립률 |
| **P-10 추천 만료** | **3일** | 집중 2주 안에 추천 → 참여 → 성립 → 초대가 돌아야 한다 | 참여 대기가 길어져 먼저 참여한 사람이 지친다 | 이메일을 하루 안 보면 놓친다 | 참여 시점 분포(추천 후 몇 시간 만에 참여하는지) |
| **P-11 시작자 재안내** | **1일** | 09와 동일 | | | |

## 4. 데이터 게이트 (OQ-8)

| 항목 | 내용 |
|---|---|
| 시점 | 공개 후 **3일째** (온보딩이 어느 정도 쌓인 뒤, 집중 기간이 끝나기 전) |
| 기준 | 온보딩 완료자 1인당 평균 **1개 이상**의 후보가 있다 |
| 통과 | Network 기능 노출. 전역 내비에 "네트워크" 등장. 기존 사용자에게 알림 "네트워크 추천이 시작되었습니다" |
| 미통과 | P-04를 4로 낮춰 재계산. 그래도 미통과면 MVP에서 Network를 노출하지 않고 운영자만 후보 수를 본다. **3까지는 낮추지 않는다**(사용자 확정, 2026-09-07). 3은 인기 관심사만으로 묶여 추천 이유가 무의미해진다 |
| 기록 | 게이트 판단 시점의 후보 수, P-04별 후보 수를 17_ASSUMPTION_REGISTER에 기록 |

## 5. 참여

| 규칙 | 내용 |
|---|---|
| 선택지 | 참여(연결하기) / 거절 / 보류(만료까지) |
| 참여 효과 | 참여자 수 갱신. 다른 멤버에게 "N명 참여"로 보임. 누가 참여했는지는 표시명으로 보임 |
| 첫 참여자 | 성립 시 **시작자**가 된다. 참여 전 확인: "가장 먼저 참여하면 성립 시 대화를 시작하는 역할을 맡습니다" |
| 시작자 부담 완화 (OQ-12) | 시작자의 역할은 "메신저에서 그룹 대화를 열고 초대"뿐이다. 첫 발언까지 요구하지 않는다. 안내 문구에 이를 명시. 성립 화면에 초대할 실명 목록 복사 버튼 |
| 만료 전 리마인드 | 만료 하루 전 미결정 멤버에게 한 번. "내일 만료됩니다" |
| 참여 철회 | 성립 전까지 가능. 철회하면 첫 참여자였더라도 시작자에서 빠지고 다음 참여자가 시작자 |
| 거절 효과 | 나는 멤버에서 제외. 그룹은 나 없이 성립 가능(단, 남은 인원이 P-09 이상일 때). 상대들에게 통보 없음 |
| 거절한 Network | 내 목록에서 사라짐. 같은 구성(멤버 집합이 동일)의 재추천 없음 |

## 6. 성립

| 규칙 | 내용 |
|---|---|
| 조건 | 만료 전 참여자가 `[P-09]` 3명 이상 |
| 시점 | 3명째가 참여하는 즉시. 나머지 멤버의 결정을 기다리지 않는다 |
| 왜 즉시인가 | 기다리면 먼저 참여한 사람이 지친다. 늦게 참여하는 사람은 성립된 Network에 **추가 참여** 가능(만료 전까지) |
| 효과 | 참여자 전원의 실명 공개. 시작자 지정. 전원에게 알림 + 성립 화면 |
| 성립 화면 | 멤버 실명 목록(복사), 공통 관심사, 시작자 Action 안내, "초대했어요" / "초대받았어요" |
| 미참여 멤버 | 성립 후에도 만료 전까지 카드가 남아 "이미 3명이 시작했습니다. 지금 참여하면 함께합니다". 만료 후 사라짐 |
| 만료 시 인원 미달 | 참여했던 사람들에게 "성립되지 않았습니다" + 서로에 대한 1:1 요청 진입점 |
| 재안내 | 시작자가 1일 안에 "초대했어요"를 누르지 않으면 나머지에게 "누구든 먼저 초대해도 좋습니다" |
| 후속 확인 | 성립 후 2일에 전원에게 "네트워크 대화가 시작되었나요?" |

## 7. 중복과 재추천

| 상황 | 규칙 |
|---|---|
| 같은 멤버 집합 | 한 번만 추천. 거절·만료 후 재추천 없음 |
| 멤버가 대부분 겹치는 그룹 (예: 4명 중 3명 동일) | 동시에 추천하지 않는다. 먼저 만들어진 것이 만료된 뒤에만 |
| 이미 성립된 Network의 멤버 | 다른 Network에도 추천 가능. 사람은 여러 모임에 속할 수 있다 |
| 성립된 Network와 같은 멤버 집합 | 재추천 없음 |
| 한 사람이 이미 3개 추천을 받고 있음 | 새 후보는 대기. 기존 것이 만료/결정되면 노출 |

---

## 8. 성립 이후

- 앱 안에 Network 대화, 게시판, 멤버 관리는 없다. 성립 화면이 유일한 흔적이다.
- Networks 화면의 "성립됨" 탭에서 언제든 멤버 실명과 공통 관심사를 다시 볼 수 있다.
- Network "탈퇴"는 없다. 메신저 그룹에서 나가면 된다.
- 성립된 Network의 존재는 멤버에게만 보인다. 다른 사람에게 "이 사람은 Network 2개에 속함" 같은 정보를 보여주지 않는다.

## 결정 / 미결정

### 결정됨

- 전원 교집합 기준. Pairwise 없음.
- P-04=5 (게이트 미통과 시 4), P-05=3~6, P-09=3, P-10=3일, P-11=1일.
- 데이터 게이트: 공개 3일째, 1인당 평균 1개 이상.
- 동시 추천 최대 3개. 후보 풀은 이벤트마다 갱신, 노출은 온보딩 즉시 1개 + 하루 2회 배치(§2a).
- 이미 연결된 사람 포함 가능, 전원 연결된 그룹은 제외.
- 첫 참여자 = 시작자. 역할은 "그룹 대화 열고 초대"까지. 철회 시 다음 참여자에게 이관.
- 3명째 참여 즉시 성립. 늦은 참여자는 만료 전까지 추가 참여 가능.
- 같은/대부분 겹치는 멤버 집합은 중복 추천하지 않음.
