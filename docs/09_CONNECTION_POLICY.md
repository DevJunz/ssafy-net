## 1. Connection의 정확한 의미

> **Connection은 "두 사람이 관심사를 바탕으로 이야기해볼 의사를 서로 확인했다"는 상태다.**

| Connection은 | Connection이 아닌 것 |
|---|---|
| 서로의 실명이 공개된 상태 | 친구, 팔로우 |
| 사내 메신저에서 먼저 말을 걸어도 되는 상태 | 이미 대화한 사이 |
| 시작자가 정해진 상태 | 지속적 관계 |
| 후속 확인의 대상 | 앱 안의 대화 |

이 정의가 화면 문구를 결정한다. "친구 추가"가 아니라 **"연결 요청"**, "친구"가 아니라 **"연결됨"**, 수락 후 문구는 "이제 대화를 시작해보세요"다.

## 2. 요청 조건

| 조건 | 규칙 |
|---|---|
| 대상 | 온보딩을 마친(관심사 최소 개수 이상) 다른 구성원 |
| 자기 자신 | 불가. 버튼 자체가 없음 |
| 이미 연결됨 | 불가. "연결됨" 표시 |
| 내가 보낸 요청이 대기 중 | 불가. "응답 대기" + 취소 |
| 상대가 나에게 보낸 요청이 대기 중 | 새 요청 불가. 대신 수락/거절로 유도 |
| 거절/만료 후 재요청 대기 중 | 불가. "N일 후 다시 요청 가능" |
| 공통 관심사 0개 | **가능.** 공통 관심사가 없어도 요청할 수 있다. 다만 요청 화면에 "공통 관심사가 없습니다. 왜 이야기하고 싶은지 적어주세요" 안내 |
| 메시지 | **필수.** 1자 이상 `[P-16]` 200자 이하. 빈 요청은 "친구 추가"와 다를 바 없다 |
| 목적 선택 (OQ-2) | **MVP에서는 두지 않는다.** 메시지가 목적을 담는다. 메시지 작성률이 낮거나 내용이 빈약하면(예: "안녕하세요"만) 목적 선택지를 추가한다 |

## 3. 요청 횟수 상한과 Spam 방지

| 파라미터 | 값 | 왜 | 너무 높으면 | 너무 낮으면 | 조정 데이터 |
|---|---|---|---|---|---|
| P-06 일일 | **5** | 하루에 5명에게 진심 어린 메시지를 쓰는 것이 현실적 상한 | 무차별 요청. 받는 쪽의 Rejection Fatigue | 적극적 사용자가 막힘. 집중 2주 동안 기회 손실 | 상한 도달 사용자 비율, 상한 도달자의 수락률 |
| P-06 주간 | **20** | 집중 2주 동안 한 사람이 최대 40명에게 요청 가능. 1,000명 조직에서 충분 | | | |

Spam 방지 장치는 횟수 상한 외에 다음이 있다.

| 장치 | 내용 |
|---|---|
| 메시지 필수 | 복사-붙여넣기 메시지는 막지 않되, 같은 메시지를 3회 이상 보내면 "각 사람에게 맞는 메시지를 써보세요" 안내 |
| 취소해도 횟수 복구 없음 | 취소로 상한을 우회하지 못한다 |
| 수락률 기반 감속 | 보낸 요청 10건 이상 중 수락률이 10% 미만이면 일일 상한을 2로 낮춘다. 사용자에게는 "요청이 잘 수락되지 않고 있습니다. 공통 관심사가 많은 사람에게 보내보세요" 안내 |
| 신고 (S5) | 요청 메시지 신고 가능. 신고 2회 이상 누적 시 운영자에게 표시, 운영자는 요청 권한 정지 가능 |

## 4. 받은 요청

| 규칙 | 내용 |
|---|---|
| 알림 | 즉시. 이메일 + 브라우저(허용 시) + 앱 내. 내용: 표시명, 공통 관심사 개수와 이름, 메시지 첫 줄 |
| 만료 전 리마인드 | 만료 하루 전 한 번. "○○님의 요청이 내일 만료됩니다" |
| 가능한 행동 | 수락 / 거절 / 무시(만료) / 신고 |
| 판단 정보 | 보낸 사람의 표시명(실명 여부), 관심사 전체, 공통 관심사, 메시지 전문, 최근 글(S1) |
| 보낸 사람이 닉네임 사용자일 때 | 위 정보로 판단하도록 안내. 수락 시 양쪽 실명이 동시에 공개되므로 위험이 대칭임을 설명 |

## 5. 수락

| 규칙 | 내용 |
|---|---|
| 효과 | 양쪽 "연결됨". 양쪽 실명 동시 공개. 시작자 지정. 양쪽에 연결 성립 화면 |
| 확인 | 닉네임 사용자만 "실명이 공개됩니다" 확인. 실명 사용자는 확인 없음 |
| 시작자 | **요청을 보낸 사람.** 이미 의사와 메시지를 냈으므로 첫 메시지를 보내는 것이 자연스럽다. 받은 사람에게는 "○○님이 먼저 연락할 예정입니다. 먼저 연락하셔도 좋습니다" |
| 동시 요청 | 서로 동시에 요청한 경우 한쪽 수락으로 양쪽 정리. 시작자는 먼저 보낸 사람 |
| 재안내 | 시작자가 `[P-11]` **1일** 안에 "메시지를 보냈어요"를 누르지 않으면, 시작자에게 "아직 연락하지 않으셨다면 지금" + 상대에게 "먼저 연락하셔도 좋습니다" |
| 후속 확인 | 성립 후 `[P-18]` **2일**에 양쪽에 "대화를 시작하셨나요?" 1회 |

## 6. 거절

| 규칙 | 내용 |
|---|---|
| 통보 | 보낸 사람에게 **직접 통보하지 않는다** |
| 보낸 사람이 보는 것 | 거절 후 `[P-08a]` **최대 1일** 안에 "응답 없음"으로 바뀐다. 만료와 같은 표시 |
| 왜 하루인가 | 즉시 표시하면 거절이 확실해져 보낸 사람이 상처받는다. 만료(3일)까지 기다리게 하면 집중 2주 중 사흘을 허비한다. 하루는 "거절인지 안 본 건지 알 수 없는" 최소 시간이면서 다음 행동으로 넘어가기에 충분히 짧다 |
| 되돌리기 | 거절 직후 5초 |
| 재요청 | `[P-07]` **14일** 후 가능. 사용 집중 기간이 2주이므로 사실상 MVP 기간 내 재요청 불가. 같은 사람에게 두 번 거절당하는 경험을 만들지 않는다 |
| 거절한 사람의 추천 목록 | 거절한 상대는 Similar People에서 **숨김**(흐림이 아니라). 다시 보고 싶으면 "숨긴 사람 보기" |
| 거절당한 사람의 추천 목록 | 거절한 상대가 "응답 없음" 표시와 함께 남는다. 재요청 가능 시점 표시 |

## 7. 만료

| 파라미터 | 값 | 왜 | 너무 길면 | 너무 짧으면 |
|---|---|---|---|---|
| P-08 요청 만료 | **3일** | 집중 2주 안에 요청 → 응답 → 대화가 돌아야 한다. 3일이면 주말을 끼어도 응답 가능 | 받은 요청이 쌓이고, 보낸 사람은 기약 없이 기다린다 | 이메일을 하루 안 보면 놓친다 |

- 만료된 요청은 보낸 쪽에 "응답 없음", 받은 쪽에서는 사라진다.
- 만료 후 재요청은 거절과 같은 `[P-07]` 대기. 만료를 "무관심"으로 해석하고 같은 대기를 둔다.

## 8. 취소 (S6)

| 규칙 | 내용 |
|---|---|
| 조건 | 상대가 처리하기 전 |
| 효과 | 상대의 받은 요청에서 조용히 사라짐. 알림 없음. 이미 나간 이메일은 회수하지 않음(상대가 눌러도 "이미 처리된 요청입니다") |
| 횟수 | 복구하지 않음 |
| 재요청 | 취소 후 같은 사람에게 **당일 재요청 불가**, 다음 날부터 가능. "보냈다 취소했다"를 반복하지 못하게 |

## 9. 연결 해제, 차단, 신고

| 항목 | 결정 | 이유 |
|---|---|---|
| 연결 해제 | **MVP에 없음** (L4) | 연결은 "대화 의사 확인"일 뿐 지속 관계가 아니므로 해제할 것이 없다 |
| 차단 | **없음** (사용자 결정, 2026-09-07) | 조직 내부 실명 기반이고 사용 기간이 2주다. 거절(재요청 14일 불가), 횟수 상한, 신고로 대신한다 |
| 신고 (S5) | 사람, 요청 메시지, 글. 운영자 확인. 신고자에게는 "확인 중" 외 결과 통보 없음 | 차단이 없으므로 운영자 개입의 유일한 경로 |
| 운영자 정지 | 신고 누적 시 운영자가 해당 사용자의 요청 권한을 정지. 정지된 사용자는 요청을 보낼 수 없고 그래프에는 남는다 | |

## 10. 연결 성립 후

| 규칙 | 내용 |
|---|---|
| 남는 정보 | 상대 실명, 공통 관심사(현재 기준), 요청 메시지, 성립일, 시작자, 대화 시작 여부 |
| 메신저 안내 | 실명 복사 버튼. 메신저 사용자 링크가 가능하면 링크. 실명은 메신저 표시명 형식 "이름_캠퍼스_반"이라 동명이인이 구분된다 |
| "메시지를 보냈어요" / "연락을 받았어요" | 누르면 대화 시작으로 기록. 재안내 대상에서 제외. 상대에게 알리지 않음 |
| 후속 확인 "아니오" 사유 | 찾지 못함 / 시간 없음 / 부담됨 / 기타. "찾지 못함"이면 상대에게 "먼저 연락해달라" 알림 제안 |
| 연결 수 표시 | 다른 사람에게 "이 사람의 연결 수"는 **보여주지 않는다.** 인기 지표가 되면 관심사보다 인기를 좇게 된다 |

## 11. 상태 정의 (제품 관점)

두 사람 A, B 사이의 관계는 항상 아래 중 하나다.

| 상태 | 의미 | 가능한 전이 |
|---|---|---|
| 없음 | 아무 일도 없음 | → A가 요청 |
| 요청 대기 (A→B) | A가 보냄, B 미처리 | → 수락 → 연결됨 / → 거절·만료 → 응답 없음 / → A 취소 → 없음 |
| 응답 없음 (A→B) | 거절 또는 만료. A에게만 보이는 상태 | → 14일 후 → 없음 (재요청 가능) |
| 연결됨 | 양쪽 실명 공개, 시작자 지정 | (해제 없음) |

## 결정 / 미결정

### 결정됨

- Connection = 대화 의사의 상호 확인. 친구가 아니다.
- 메시지 필수, 목적 선택은 MVP에 없음. 공통 관심사 0개여도 요청 가능.
- 일 5 / 주 20, 취소해도 복구 없음, 수락률 10% 미만이면 감속.
- 시작자 = 요청 보낸 사람. 재안내 1일, 후속 확인 2일.
- 거절 비통보, "응답 없음" 표시는 최대 1일, 재요청 14일 후. 거절한 사람의 추천에서 상대는 숨김.
- 요청 만료 3일, 만료 하루 전 리마인드.
- 연결 해제 없음. 차단 없음(신고와 운영자 정지로 대신). 연결 수 비공개.

### 미결정

| 항목 | 담당 |
|---|---|
| "같은 메시지 3회" 판정의 기준 | 구현 단계 |
| 수락률 감속 임계값 10%의 실제 값 | 공개 후 데이터 |
