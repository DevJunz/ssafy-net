# 19. Planning Handoff Summary

| 항목 | 내용 |
|---|---|
| 문서 상태 | v1.0 (Step 7, 기획 완료) |
| 작성일 | 2026-09-07 |
| 목적 | 개발 설계(ERD, API, Architecture)로 넘기기 위한 요약. 상세는 각 문서 참조 |

이 문서는 기획 문서 18개를 개발 설계자가 오해 없이 시작할 수 있는 수준으로 압축한 것이다. 여기에 없는 것은 각 문서에 있고, 여기 있는 것과 각 문서가 다르면 **각 문서가 우선**한다(이 요약이 오래되었을 가능성이 높다).

## 1. 한 줄 정의

> 단일 캠퍼스 약 1,000명 안에서, 관심사 그래프로 아직 모르는 사람을 발견하고, 서로 대화할 의사를 확인한 뒤, 실제 대화는 사내 메신저에서 실명으로 시작하게 하는 서비스. **Discover → Understand → Connect.** 대화는 서비스 밖.

| M10 | Connections (받은/보낸/연결됨) | 리스트 화면. 연결됨에 실명, 공통 관심사, 메시지, 시작자, 대화 시작 여부 | 05 §3.8 |

차단 기능은 **없다**(사용자 결정). 연결 해제도 없다.

## 5. 핵심 Policy 요약

| 영역 | 규칙 |
|---|---|
| **공개 범위** | 연결 전: 표시명, 관심사, 글. 연결 후: 실명 추가(양쪽 동시). 비공개: 로그인 계정, 연결 관계, 연결 수, 요청 이력, 거절, 신고. 조직 밖: 없음 |
| **Connection 의미** | "관심사를 바탕으로 이야기해볼 의사의 상호 확인". 친구가 아님. 지속 관계 아님 |
| **시간 (2주 집중 전제)** | 요청 만료 3일(하루 전 리마인드) · 거절 표시 ≤ 1일 · 재요청 대기 14일 · Network 만료 3일 · 시작자 재안내 1일 · 후속 확인 2일 · 묶음 알림 첫 2주 일 1회 |
| **추천 설명** | 점수·퍼센트 비노출. 관심사 이름 전부 노출. 정렬 기준 화면에 명시. 설명 불가능한 점수 사용 안 함 |
| **인기 관심사** | 제거하지 않음. 정렬 동점 처리에 희소성 가중. 세분화는 운영자 검토 |
| **관심사 운영** | 삭제 대신 숨김. 병합·숨김은 사용자 알림. 변경은 언제든 즉시 반영 |
| **게시글** | Context 생성 수단. 커뮤니티 아님. 만료 없음 |
| **안전** | 메시지 필수, 횟수 상한, 수락률 감속, 신고, 운영자 정지. 차단 없음 |

Product Parameter 전체(P-01~P-18)는 02 §8. 그래프 상한(P-13~15)은 앱 완성 후 조정.

## 6. 주요 User Flow

```
[초대 링크] → Google 로그인 → 실명(이름+반) → 표시명(닉네임/실명) → 관심사 5~15 → 알림 설정 → 그래프(홈)

그래프 ─┬─ 관심사 클릭 → Interest 상세(사람 목록, 글) → 사람 클릭
        ├─ "비슷한 사람 보기" → Similarity Edge + 목록 → 사람 클릭
        └─ (S2) 추천 네트워크 → 허브 + 멤버 → 참여
                                                    │
                                              Person Profile
                                                    │
                                     연결 요청(메시지 필수) ──▶ 상대에게 즉시 알림
                                                    │              │
                                                    │        요청 상세 → 수락 / 거절 / 무시
                                                    │              │ 수락
                                                    ◀──────────────┘
                                          연결 성립 화면 (양쪽 실명, 시작자 Action 안내)
                                                    │
                                          사내 메신저 (서비스 밖) → "메시지를 보냈어요"
                                                    │
                                          2일 후 후속 확인 "대화를 시작하셨나요?"
```

알림(이메일/브라우저/앱 내)은 모두 홈이 아닌 **행동 화면에 직행**한다. 상세 Journey는 04, 화면은 05~06, 인터랙션은 07.

## 7. 화면 (Must)

Onboarding 5단계 · Graph + 패널 4종(기본, Interest, Person, Similar) · Connections 3탭 · Notifications · My Profile · Settings · Overlay 4종(요청 작성, 요청 상세, 연결 성립, 후속 확인). 모바일은 Connections, Notifications, Overlay만.

## 8. 측정

- **North Star**: 신규 성립 연결 수(Network 성립은 인원 수 환산). 목표 첫 2주 40건.
- **가드레일**: 후속 확인 "대화 시작" 응답 ≥ 50%.
- 판단 시점 1, 3, 7, **14**(중간 판단), 28일. MVP 4주(집중 2 + 관찰 2).
- 수집할 사건 목록은 14 §6.

## 10. 개발 설계자에게

- 이 문서 묶음은 **무엇을 만들지**만 정한다. 어떻게 만들지(데이터 구조, API, 스택, 인프라)는 정하지 않았고, 정하지 않은 것이 의도다.
- 설계 중 제품 결정이 필요한 지점이 생기면 16_PRODUCT_DECISION_LOG에 추가하고, 가정이 생기면 17_ASSUMPTION_REGISTER에 등록한다.
- PM 의견과 다르게 결정된 항목 3개(닉네임 공존, 거절 표시 하루, 차단 없음)는 16 말미에 관찰 지점과 함께 있다. 재논의 대상이 아니라 측정 대상이다.
- 그래프 세부(간격, 크기, 상한)는 문서로 확정하지 않았다. 첫 구현 후 실사용 피드백으로 정한다(D-34).
