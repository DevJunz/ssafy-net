| 항목 | 내용 |

법률 문구가 아니라 **"무엇이 누구에게 언제 보이는가"**의 제품 규칙이다. 원칙은 하나다. 사용자는 온보딩, 요청, 수락 시점마다 그 행동으로 무엇이 공개되는지 미리 알 수 있어야 한다(NFR-3).

## 2. 실명

| 규칙 | 내용 |
|---|---|
| 입력 | 온보딩 필수. "사내 메신저에 표시되는 이름 그대로" |
| 형식 | **"이름_캠퍼스_반"** (예: 최준환_서울_18반). 사내 메신저 표시명과 동일. 이름과 반을 따로 입력받아 조합. 반이 동명이인을 구분한다 |
| 검증 | 없음. 사용자를 신뢰한다. 허위 실명은 연결 후 메신저에서 못 찾는 결과로 드러나며, 후속 확인 "찾지 못함"으로 관찰한다 |
| 수정 | My Profile에서 가능. 이미 연결된 상대에게는 새 실명이 보인다 |
| 공개 시점 | **연결 성립 시 양쪽 동시.** 한쪽만 먼저 공개되는 경우는 없다 |
| 공개 안내 | 세 번: 온보딩 첫 화면, 실명 입력 시, (닉네임 사용자) 수락 확인 시 |

## 3. 표시명

| 규칙 | 내용 |
|---|---|
| 선택 | 닉네임 또는 실명. 온보딩에서 선택, My Profile에서 변경 |
| 실명 표시 | 실명을 표시명으로 쓰는 사용자에게는 구분 표시가 붙는다. 닉네임 사용자와 혼동되지 않게 |
| 닉네임 규칙 | 2~12자. 중복 불가. **다른 구성원의 실명과 같거나 유사한 닉네임 불가**(실명 사용자로 오인 방지). 부적절 표현 불가. 조직명, 운영자 사칭 불가 |
| 유사 판정 | 실명과 완전 일치, 또는 실명에서 한 글자만 다른 경우. 검사는 기존 사용자의 실명 전체를 대상으로 |
| 변경 | 언제든. 변경 시 진행 중 요청의 상대와 추천 목록에 새 표시명이 보인다. 변경 이력은 상대에게 보이지 않는다 |
| 변경 남용 | 하루 1회 |

---

## 4. 관심사와 글

- 관심사와 글은 조직 구성원 전체에 공개된다. 비공개 옵션은 없다. 온보딩에서 명시한다.
- 관심사 목록에 민감 주제(종교, 정치, 건강, 성적 지향)를 넣지 않는 것으로 사용자를 보호한다(08 §7).
- 글에 개인정보(전화번호, 주소)를 쓰면 신고 대상이다.

---

## 5. 요청, 연결, 거절

| 규칙 | 내용 |
|---|---|
| 요청 메시지 | 보낸 사람과 받은 사람만. 연결 성립 후에도 두 사람에게만 남는다 |
| 거절 | 상대에게 통보하지 않는다. "응답 없음"으로만 |
| 연결 수, 요청 수 | 다른 사람에게 보여주지 않는다. 인기 지표를 만들지 않는다 |
| 연결 관계 | 제3자에게 보이지 않는다. "A와 B가 연결됨"을 C는 알 수 없다 |
| 대화 시작 여부 | 상대에게도 알리지 않는다. 메신저에서 알게 된다 |

---

## 6. Network

- 추천 단계: 같은 후보의 멤버끼리는 서로의 표시명과 참여 여부를 본다. 후보 밖 사람은 이 후보의 존재를 모른다.
- 성립 후: 참여 멤버끼리 실명 공개. 거절한 사람과 미참여자는 성립 멤버의 실명을 보지 못한다.
- 성립된 Network의 존재는 멤버에게만. 제3자에게 "이 사람은 Network N개 참여"를 보여주지 않는다.

---

## 7. 알림 채널

- 이메일 주소와 외부 채널 정보는 알림 발송에만 쓴다. 다른 구성원에게 보이지 않는다.
- 알림 본문에는 판단에 필요한 최소 정보만(표시명, 공통 관심사, 메시지 첫 줄). 실명은 연결 성립 알림에만.
- 외부 채널(S3a)로 나가는 알림에는 실명을 넣지 않는다. 채널이 조직 밖 서비스이기 때문이다. "연결이 성립되었습니다. 앱에서 확인하세요"까지만.

---

## 8. 차단

차단 기능은 제공하지 않는다(사용자 결정, 2026-09-07). 원치 않는 접근에 대한 보호는 거절 비통보, 재요청 14일 불가, 요청 횟수 상한, 신고와 운영자 정지로 한다. 신고 사실은 상대에게 통보되지 않는다.

---

## 9. 운영자

| 규칙 | 내용 |
|---|---|
| 볼 수 있는 것 | 위 표의 운영자 열. 신고 처리에 필요한 요청 메시지와 글, 집계 지표 |
| 볼 수 없는 것 | 개별 사용자의 요청 메시지를 신고 없이 열람하지 않는다(정책적 약속. 기술적 차단은 아님) |
| 운영자 계정 | 일반 사용자와 같은 계정으로 활동하되 운영자 표시. 운영자도 관심사를 등록하고 연결할 수 있다 |
| 통계 | 개인 식별 없는 집계만 조직에 공유(예: "이번 주 성립 연결 40건") |

## 10. 탈퇴와 데이터

| 규칙 | 내용 |
|---|---|
| 탈퇴 | Settings에서. 확인 후 즉시 |
| 삭제되는 것 | 프로필, 관심사, 글, 보낸/받은 요청, 연결, Network 참여, 신고 이력, 알림 설정 |
| 상대에게 남는 것 | 연결됨 목록에서 "탈퇴한 사용자"로 표시. 실명은 지운다. 받은 요청 메시지는 지운다 |
| 집계 지표 | 개인 식별 없는 집계(요청 수, 성립 수)에는 남는다 |
| 재가입 | 같은 계정으로 가능. 이전 데이터는 복구되지 않는다 |
| MVP 종료 시 | 서비스를 계속하지 않기로 하면 전체 데이터를 삭제하고 사용자에게 알린다. 계속하면 그대로 유지 |

---

## 11. 사용자에게 보여줄 공개 범위 요약 (화면 문구용)

온보딩 첫 화면과 My Profile "연결 전/후 미리보기"에서 쓰는 문구다.

> **연결 전**: 표시명(닉네임 또는 실명), 관심사, 내가 쓴 글이 조직 구성원에게 보입니다.
> **연결 후**: 연결된 상대에게만 실명이 추가로 보입니다.
> **보이지 않는 것**: 로그인 계정, 누구와 연결됐는지, 누가 요청했는지, 거절과 신고.
> **조직 밖**: 아무것도 보이지 않습니다.

## 결정 / 미결정

### 결정됨

- 정보별 공개 범위 표(§1). 실명은 연결 시 양쪽 동시 공개. 연결 수, 연결 관계, 거절, 신고는 제3자와 상대에게 비공개.
- 실명 형식 "이름_캠퍼스_반". 차단 기능 없음.
- 닉네임은 다른 구성원 실명과 유사하면 불가. 변경 하루 1회.
- 관심사와 글은 전원 공개, 비공개 옵션 없음.
- 외부 채널 알림에 실명 미포함.
- 운영자는 신고 없이 요청 메시지를 열람하지 않는다(정책적 약속).
- 탈퇴 시 개인 데이터 전부 삭제, 집계만 유지.
