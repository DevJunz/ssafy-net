## 확정 사항 (2026-09-08, 사용자)

- 스택: **NestJS + PostgreSQL + Prisma**, 프론트는 React + Vite
- 프론트엔드는 **새 `web/` 앱**. `phase0-mvp/`는 보존하고 그래프 렌더링 로직만 이식
- 진행 방식: 설계 문서 3종 → 검토 → 구현
- B-3(이메일)·B-4(외부 채널) 테스트는 구현 중에. 설계는 채널 어댑터로 추상화

## 구현 진행

| 마일스톤 | 상태 |
|---|---|
| M1 기반 (스키마·인증·온보딩) | 완료 |
| M2 발견 (그래프·Similar People) | 완료 |
| M3 연결 (요청·수락·성립·후속 확인) | 완료 — **Must 사슬 완성** |
| M4 알림 | 완료 — 발송·알림함·딥링크·배치 10종 |
| M5 Should | 완료 — Network, Post, 제안, 묶음 알림. 신고는 만들지 않음(D-69) |

구현하면서 설계와 달라진 곳은 해당 문서에 이유와 함께 적었다. 가장 큰 변경은
Network 후보 탐색을 클리크 열거에서 탐욕적 확장으로 바꾼 것이다(20 §6.3, D-65).

## 우선순위 규칙

1. 제품 규칙이 충돌하면 `docs/`가 우선한다.
2. 기술 판단이 충돌하면 `design/`이 우선한다.
3. 설계 중 생긴 **제품 결정**은 `docs/16`에, **가정**은 `docs/17`에 넣는다(docs/19 §10). D-60~D-65는 반영 완료.
